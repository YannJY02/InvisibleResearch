# 研究报告规范

本规范适用于本仓库向导师、研究合作者展示的会前报告、研究进展报告和数据分析报告。
每次新建、修改或重新输出这些报告时，均须在写作前阅读本文件，并在交付前完成末尾检查。
无需用户在每个任务中重复说明。

## 来源与适用范围

这是**用户明确提出的要求**，不是学校或期刊的投稿规范。来源为 2026-09-15
Crossref/OpenAlex 会前报告讨论中的连续反馈，主要原话为：

- “报告的内容应该是严格对应这些任务需求的”；“只关注下一次会议当中要去做的事情”。
- “报告其实就是 R 渲染出来的这个产物”；“展示对应的这个最小可实现的代码”。
- “重点还是应该放在这个结果的解释上，或者是结果的描述上”。
- “在每一项报告开始的时候去列出……我们约定好的这个任务是什么”。
- 字段比较要把同一案例的列名、说明和内容并排展示，独有内容放在后面。
- 后续明确要求展开双方期刊字段、重新输出报告，并将格式与风格要求写入文档持续执行。

以下结构和检查项落实这些要求。沿用目标报告已约定的语言、读者和格式；用户后续对
具体任务的明确要求优先。R 执行要求适用于 R 数据分析报告，不要求会议纪要、文献叙述
或其他纯文字材料为了形式而加入代码。Nature、特定字段数和本次会议的四项任务均是
案例约定，不是所有后续报告的固定内容。

## 1. 任务决定内容

- 写作前从用户指令、会议记录和已关联任务中确认本次要回答的问题；每个主要部分都要
  对应一项已约定任务。已有来源能够解决的问题，先查来源，不让用户重复回忆。
- 会前报告只纳入本次会议需要讨论的工作。不能因已经做过、技术上有趣或未来可能有用，
  就自行加入新的数据母体、模型或分析。某次会议不需要 SHAP，不等于以后禁止报告 SHAP。
- 每项开头用一句朴素的话写明“约定任务”。这句话应让合作者直接判断双方对任务的理解
  是否一致；方法和结果都围绕它展开。

## 2. 固定信息顺序，突出结果意义

每项按下列顺序组织；纯文字任务省略代码部分：

1. **约定任务**：我们答应查清或完成什么。
2. **最小可运行代码**：实际如何取得或计算下方结果；必要时加一句逻辑说明。
3. **结果**：直接呈现对应的表格、图或简短事实。
4. **解释**：结果说明了什么，对本次研究问题或会议判断有什么意义。

用短段落、清楚的标题和便于比较的表格组织内容。重要结果和解释直接可见；辅助函数、
较长的字段说明代码及重复列表的完整值可以折叠，但应能在同一份报告中查看。
简短不等于省略用户要求的完整字段或必要证据，也不设脱离任务的统一字数或页数限制。

## 3. 面向没有技术背景的合作者

- 用普通词语和具体案例解释结果，少用术语；必须使用的术语在首次出现时简要说明。
  技术细节主要由代码承担，正文不逐行复述实现。
- 删除重复结论、操作流水账、内部调试说明和冗长的自我免责表述。只保留会改变读者理解
  或影响下一步判断的限制，紧邻相关结果简短说明。
- 保持解释准确：数据为空、获取失败、没有匹配对象和事物本身不存在是不同结果；
  一个案例的观察不能写成所有期刊的结论，来源记录也不能直接当作研究质量或因果证据。
- 权限测试在正文中只需给出最小测试代码，并用一句话交代是否成功及仍需要的权限。
  详细错误日志和工具选择经过保留在工作产物中，除非它们就是本次讨论的任务。

## 4. 代码、数据与报告是同一次执行的产物

- R 分析以 QMD/Rmd 为报告源文件，表格、数字和图由其中实际执行的 R 代码产生。
  不能只摆放示意代码，再手工制作看似由这些代码生成的结果或 HTML。
- 使用缓存时说明来源及时间，并在报告源文件中保留获取该缓存所需的代码和重跑入口。
  清楚区分原始数据、人工编写的字段解释/对应关系，以及计算结果；不把说明表称为 API 数据。
- 修改报告后重新执行和渲染，再检查最终页面。交付源文件与最新可读产物的链接；
  产物放在所属分析的忽略目录 `artifacts/<pipeline>/`，按仓库规则提交并推送源码。
- 是否发布由已有授权决定；本地渲染、上传成功和公开可访问分别按实际验证结果报告。

## 5. 字段对照报告的附加要求

- 用**同一个可确认身份的案例**比较双方，遵循用户指定的案例和对象层级。相关字段
  使用相同年份或同一列表条目举例；期刊字段与论文字段不能直接当作同层级对应项。
- 并排列出“来源 A 字段名与说明、案例值、来源 B 字段名与说明、案例值”。相同或相似
  信息在前，独有字段在后，无对应项的一侧留空；含义相似但口径不同的地方应说明。
- 在约定范围内完整列出双方字段。要求展开时，每个子字段有独立可见的字段路径与说明，
  不以大段 JSON 或少量摘录代替完整字段清单。重复列表可以展示一个明确条目并展开全部值。
- 区分实际返回的 `null`、空列表、未返回的可选字段和没有对应列；空列表无法提供的
  子字段案例不能凭空补造。完整性应对照实际输入/响应检查，不能只核对手工挑选的清单。
- 表格后用自然语言说明共同信息、真正增加的信息及其研究用途；数据库内部的重复字段
  不应被描述成多个独立发现。

## 每次交付前的检查

逐项核对并修正不符合之处，无需另外生成一份检查报告：

- **范围与结构**：每部分能对应已约定任务，开头写明任务，没有未经要求的扩展分析。
- **语言与解释**：非技术读者能够理解主要结果及其意义，正文没有被调试或防御性说明淹没。
- **执行与来源**：展示代码确实运行；结果来自标明来源的数据；修改后的报告已重新渲染。
- **展示与完整性**：打开最终页面检查表格、图和折叠内容；字段比较核对同一案例、
  子字段覆盖和空值呈现，确保没有遗漏或误配。
- **交付**：提供正确产物入口，完成仓库要求的检查、提交和推送；验证记录简要写入已有
  交付记录或关联任务，不增加无必要的审批步骤。

文档治理检查负责路径、命名和链接；任务对应、解释质量及结果可读性仍需按上述项目
实际审阅。不能用“自动检查通过”代替报告内容和渲染检查。
